# کانال پیکربندی امضاشده (Remote Config)

پارامترهای ضدسانسور باید **سریع‌تر از انتشار نسخه‌ی جدید اپ** تغییر کنند: وقتی DPI اپراتور رفتارش عوض می‌شود، پروفایل فرگمنت و لیست فینگرپرینت‌ها باید همان روز عوض شوند، نه با انتشار APK. این کانال همان مکانیزم است — با امضای Ed25519 و کلید عمومیِ سنجاق‌شده در اپ (الگوی msn-guard/shroudly).

## چه چیزی از کانال می‌آید

فایل `remote-config/remote-config.json`:

| فیلد | اثر | جای مصرف |
| --- | --- | --- |
| `fragmentProfiles` | پروفایل‌های فرگمنت TLS (جديد یا اصلاح‌شده) | `TlsFragmentProfiles.specOf()` |
| `fingerprints` | لیست کامل فینگرپرینت‌های چرخش uTLS | `FingerprintRotator.candidates()` |
| `warpEndpoints` | نقاط anycast کلادفلر (IP + پورت) | `WarpEndpoints.anycastIps()/ports()` |
| `configSources` | لیست کامل منابع کانفیگ رایگان | `BuiltInSources.sourceUrls()` |
| `notes` | یادداشت فارسی برای نمایش در تنظیمات | UI وضعیت کانال |

هر فیلدی که خالی باشد، مقدار داخلی اپ دست‌نخورده می‌ماند.

## جریان اعتماد

1. کلید خصوصی Ed25519 **فقط** در GitHub Secret نگه‌داری می‌شود (`REMOTE_CONFIG_SIGNING_KEY` = base64 از PEM).
2. ورک‌فلو `remote-config.yml` با هر تغییر در `remote-config/` فایل را امضا می‌کند و جفتِ «فایل + امضا» را به‌صورت رولینگ-ریلیز با تگ `remote-config` منتشر می‌کند.
3. اپ `<url>` و `<url>.sig` را می‌گیرد (پیش‌فرض: همان ریلز گیت‌هاب؛ از داخل تونل اگر بالا باشد، وگرنه مستقیم)، امضا را با کلید عمومی سنجاق‌شده در `RemoteConfigChannel.PUBLIC_KEY_B64` بررسی می‌کند و **فقط در صورت معتبر بودن** اعمال می‌کند.
4. آخرین کانفیگ *تأییدشده* در `filesDir` ذخیره می‌شود و در هر اجرای بعدی اپ (حتی آفلاین) دوباره اعمال می‌شود.

هر خرابی — دانلود ناموفق، امضای نامعتبر، JSON خراب — به معنی «ادامه با تنظیمات فعلی» است؛ کانال هرگز نمی‌تواند اپ را بشکند.

## کلیدها

تولید جفت‌کلید جدید:

```bash
./tools/gen-remote-config-key.sh
```

خروجی: کلید عمومی (که در کد سنجاق می‌شود — تغییرش نیازمند انتشار اپ است) و کلید خصوصی (که به‌عنوان Secret ذخیره می‌شود؛ هرگز کامیت نمی‌شود).

امضای دستی و تست:

```bash
REMOTE_CONFIG_KEY_FILE=remote-config-private.pem ./tools/sign-remote-config.sh
```

## نکته‌ی عملیاتی برای نگهدارنده

- تغییر پروفایل‌ها = ویرایش `remote-config/remote-config.json` + کامیت روی `main`. ورک‌فلو امضا و انتشار را انجام می‌دهد. کاربران با «بررسی به‌روزرسانی» در تنظیمات یا اتصال بعدی می‌گیرندش.
- اگر کلید لو رفت: جفت‌کلید جدید بساز، کلید عمومی را در کد سنجاق کن، نسخه‌ی جدید اپ منتشر کن و Secret را عوض کن. کانفیگ‌های امضاشده با کلید قدیمی از آن پس رد می‌شوند — این دقیقا همان رفتار مطلوب است.
- حجم فایل باید کوچک بماند (سقف اپ: ۲۵۶ کیلوبایت؛ سقف عاقلانه: چند کیلوبایت).
